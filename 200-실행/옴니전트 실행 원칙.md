# 옴니전트 실행 원칙

#200-실행 #옴니전트 #AI에이전트 #인프라 #보안

옴니전트 도입의 실행 원칙은 하이브리드 인프라 배치, 저지연 상태 저장, 프롬프트 하부 거버넌스의 세 가지로 요약된다. 여러 에이전트를 묶는 것만으로는 충분하지 않고, 어디서 실행할지, 상태를 어디에 남길지, 위험 행동을 어떤 계층에서 막을지를 함께 설계해야 한다.

## 원칙 1. 워크로드별 실행 위치를 나눈다
무거운 컴파일, 대규모 소스 변경, 격리 보안이 필요한 작업은 클라우드 VM에 배치하고, 가벼운 코드 리뷰나 시각화 중계는 로컬 단말에서 조율한다. 목적은 비용, 속도, 보안을 동시에 관리하는 것이다.

## 원칙 2. 세션 상태를 저지연 저장소에 남긴다
에이전트 세션은 비정상 종료나 컨텍스트 소실에 취약하다. 단순 파일 저장에만 의존하지 말고, 저지연 OLTP 데이터베이스 같은 상태 저장소를 결합해 세션 상태와 대화 컨텍스트를 복원 가능하게 둔다.

## 원칙 3. 보안은 프롬프트보다 아래 계층에서 강제한다
“위험한 일을 하지 마라”는 프롬프트 지시는 보안 장치가 아니다. OS 수준 샌드박싱, 권한 분리, 크리덴셜 브로커링, 정책 필터처럼 실행 계층에서 강제되는 통제 장치를 둬야 한다.
