# 240412 CRM 액션 커뮤니케이션 오류

#100-지식

Situation: 앰플리튜드 교육중 shane이 저번에 CRM을 앰플리튜드로 뽑을 수 있다고 했다. 

Task: (실제 이 상황에서 내가 해결해야할 문제는 무엇이었는지.)
CRM 액션을 위한 sql 코드를 바로 짜야했고, 미팅때 내부 db와 앰플리튜드를 너무 방대하게 설명한 것이 문제가 아니었나 싶다.  DB,sql, 빅쿼리, 앰플리튜드 이런 단어들 사용하지 말자. 
Action: 
커뮤니케이션 오류에 대해 일어났던 일에 사과하고, 지호님에게 sql 피드백 더블 체크를 빠르게 했던 것이 잘했던점. 
(지호님이 sql의 속도와 구조방향 설계를 잘하시는데 우리가 뭘 더 잘해볼 수 있을까?) 
Result(예측): 
CRM에 대한 요구가 더 늘어나지 않을까 싶다. 
 Result(실제):
요건 현재 진행 중 

Reflection:
(어떤 점이 핵심 성공 요인이었다고 생각이 들고, 어떤 점이 특히 아쉬운 지점인지. 다시 이 문제를 접한다면 어떤 점 한 두 가지를 다르게 시도해보고 싶은지. 다음번에 더 잘하기 위해 어떤 연습, 준비, 노력을 미리 해두고 싶은지.)
: 빠른 대응과 액션이 중요하다고 본다. 이걸 우리가 매우 잘하는 것 같다. 다만 우리가 해결할 수 없는 영역에서 발생했더라면 우리가 잘해낼 수 있었을까 싶었던 지점도 있다. sql 훈련을 더 잘해야하나 아니면 프론트로 고객사가 데이터 세그먼트를 나눠서 자동화 해주는 과정을 더 잘 만들어야하나? 
기존의 나라면? 
내가 만약 혼자였다면 시간도 느려지고 어설프게 했을것 아마 GPT만 활용하지 않았을까 싶기도 하고.. 

Next Step :
우리가 프론트엔드를 더 빠르게 구현할 필요가 있다. 프로토타입 기반으로 빠른 피드백과 정성인터뷰를 통해 시퀀스 샘플링을 시도해서 더 나은 창의적 결과물을 만들어내야한다. 우리랑 잘맞는 프론트개발자가 필요하고 그걸 지속가능한 자본흐름도 넉넉해야할 것. (편하게 개발하려면)
