# GTM과 테라폼에 관해

#100-지식

[https://discord.com/channels/1079998619500945508/1234332013985796228/1338897836707942412](https://discord.com/channels/1079998619500945508/1234332013985796228/1338897836707942412)
IaC 얘기와 GTM 얘기가 같이 나와서 기억난건데, 아이디어 공유 차원에서... 저는 인프라 관리할 때 IaC를 유용하게 사용합니다. AWS 관련한 설정은 모두 github 코드에 들어가 있죠. 이게 진가를 발휘할 때는, 같은 구성을 다른 환경에 구축할 때입니다. 이를테면 프로덕션 환경과 같은 구성으로 스테이징 환경을 구축한다던지 할 때, IaC가 마련되어 있지 않으면 그 방대한 구성을 동일하게 다시 구축하기란 어렵습니다. 또, 고객사에 private cloud로 구축해줄 때도 활용할 수 있고요. 그런데 제가 IaC의 혜택을 누리지 못하는 곳이 몇 군데 있는데, 그 중 하나가 GTM입니다. GTM은 일일이 GUI에서 클릭 클릭해서 설정하는 반복 작업을 해야 하더라고요. 물론 컨테이너 구성을 JSON으로 export하고, 그걸 다시 import 할 수는 있는데, 그게 그나마 없는 것보다는 낫긴 하지만, import/export를 API로 할 수는 없어서 웹에 접속해서 해야 하기도 하고... 아, Google Tag Manager도 API가 있기는 하더라고요. 근데 IaC처럼, 선언적으로, idempotent하게 동작하는건 아니라서... idempotent하게 동작하게 하려면, 기존의 상태와, 선언된 상태를 비교해서, difference를 구하여, 없는건 생성하고, 불필요하게 있는건 제거해주면 되긴 합니다. 그래서, 일종의, Terraform for Google Tag Manager 같은걸 오픈소스로 만들어볼까 하는 생각을 했었어요. 그런게 있으면 여러 가지로 편리한 점이 있는데, 최근에 회사에서 GA뿐 아니라 MixPanel에도 이벤트를 쏘도록 장치를 해놨는데, GTM에서 기존에 설정해둔 것들 중에 Trigger는 공통으로 쓰면 되는데 Tag는 기존의 GA랑 쌍으로 똑같이 추가해줘야 하더라고요. 이런걸 선언 설정파일로 처리하면 굉장히 쉽게 되기도 하고, GTM 설정 상태도 형상관리를 할 수도 있고. 설정파일에서 전체를 쭉 훑어보면서 네이밍을 일치시킨다던지 하는 다듬는 작업을 할 수도 있고. 일일이 클릭해서 들어가서 보지 않아도요. 그리고 그게 되면, 웹개발 코드가 있는 경우 (기성 쇼핑몰을 쓰는게 아니라, 코드를 가지고 개발하는 경우)에는, GTM 선언 파일과, 웹 코드를 로컬에서 검증해봐서, HTML id값이 달라졌다던지 하는 것을 미리 디텍트할 수도 있을 것 같고요. 이미 누가 만들어놨을법도 한데, 아무래도 GTM은 개발자가 직접 다루는 분야가 아니라서 그런지, 소프트웨어 엔지니어링의 best practice가 아직은 미치지 않은 것 같은 느낌이예요. 그나마 제가 발견했던건 [이 정도](https://www.reddit.com/r/GoogleTagManager/comments/1cplt57/gtm_as_a_code/)? 뭐 이런 생각을 해봤었지만, 더 급하고 중요한 것들이 있어서, 언젠가는 해봐야지... 하고 생각만 하고 있긴 합니다.
