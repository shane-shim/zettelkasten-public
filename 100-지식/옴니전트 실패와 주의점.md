# 옴니전트 실패와 주의점

#100-지식 #옴니전트 #실패패턴 #주의점 #AI에이전트

옴니전트의 위험은 개념 자체보다 운영 복잡도에서 발생한다. 여러 하네스와 실행 환경을 묶는 순간 설치, 상태 동기화, 스트림 처리, 비용 관리, 프로토콜 호환성 문제가 동시에 생긴다.

## 주의점
- 초기 구축 부하가 크다. Python, Node.js, tmux, bubblewrap, Seatbelt 같은 런타임과 격리 도구를 직접 맞춰야 할 수 있다.
- 하네스마다 상호작용 방식이 달라 양방향 대화나 피드백 루프 구현 품질이 달라진다.
- TUI 화면, 웹 대화창, 로그 스트림 사이의 상태 동기화가 어긋나면 사용자는 같은 세션을 보고 있다고 믿지만 실제 상태는 다를 수 있다.
- 오케스트레이터가 토큰 예산을 제한해도 VM 기동비, 디스크, 네트워크, 운영 비용은 별도로 남는다.
- MCP 같은 최신 프로토콜과 기존 하네스의 호환성이 완성되지 않으면 수동 패치와 디버깅 비용이 생긴다.

## 판단 기준
옴니전트는 “설치하면 복잡도가 사라지는 도구”가 아니라 “복잡도를 한곳에서 통제하게 해주는 도구”로 봐야 한다. 따라서 도입 전에는 관리할 에이전트 수, 실행 환경 수, 보안 요구, 상태 복원 요구가 충분히 큰지 확인해야 한다.
